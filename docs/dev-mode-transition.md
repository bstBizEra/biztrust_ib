## Problem and decision

`DEMO_MODE=true` runs the loopback synthetic demonstration. `DEMO_MODE=false` alone still selects the blocked production path. A boolean cannot identify a safe intermediate environment while keeping demo sessions, simulators and future live provider adapters separate. The bounded technical choice is `APP_MODE=demo|development|staging|production`, with `DEMO_MODE` retained temporarily for existing local setup. Contradictory values fail startup. Runtime mode identifies the environment boundary; it never grants product, payment, insurer or production authority.

The first development increment is deliberately read-only: loopback host, origin and database; synthetic catalogue and health only; all other `/api/*` and `/ops/*` requests return `503 DEVELOPMENT_READ_ONLY` before authentication, webhook or domain processing. `staging` and `production` still fail startup. This permits examination of the non-demo configuration path without enabling transactions. A usable development sign-in or application journey is a later, separately verified increment.

| Mode          | Current startup                            | Available HTTP surface                                                               | Data and provider boundary                                                |
| ------------- | ------------------------------------------ | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| `demo`        | Allowed on loopback with local database    | Existing synthetic journeys and explicit simulators                                  | No real product, payment or coverage                                      |
| `development` | Allowed on loopback with loopback database | `GET /api/health` and `GET /api/catalog`; other API and operations routes return 503 | Synthetic catalogue only; no sign-in, transactions or provider adapter    |
| `staging`     | Rejected                                   | None                                                                                 | Requires an accepted sandbox topology and contracts before implementation |
| `production`  | Rejected                                   | None                                                                                 | Requires reviewed gate change, G1–G6 evidence and signed promotion        |

`APP_MODE=development` may be paired with legacy `DEMO_MODE=false` or with `DEMO_MODE` unset. `DEMO_MODE=true` with development fails as a conflict. Local setup still emits legacy demo configuration; the example environment file uses `APP_MODE=demo`. The development startup requires an isolated local PostgreSQL instance and test-only credentials, configured outside Git. No existing shared database, provider credential or external service is adopted by this proposal.

## Trade-offs and open decisions

An explicit mode makes impossible states easier to reject than two independent booleans. It adds migration work for the current `config.demo` callers and local scripts; that work should stay incremental. The first development mode has no transaction journey, so it cannot claim provider readiness or staging parity. The owner decision still needed is the exact development and staging topology, including identity test clients, sandbox contracts, hosting and service targets. No automatic deployment job or production credential is introduced.

This aligns with [Twelve-Factor configuration](https://www.12factor.net/config), [dev/prod parity](https://www.12factor.net/dev-prod-parity) and [build/release/run separation](https://www.12factor.net/build-release-run). [OWASP secret management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html) supports separate development and production secrets. [GitHub environments](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments) can add deployment protection if the selected account/repository supports and configures it; this proposal claims no such setting is active.
